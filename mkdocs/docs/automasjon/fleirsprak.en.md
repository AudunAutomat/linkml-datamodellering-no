# Multilingual portal {#fleirsprakleg-portal}

!!! note "Description"

    The documentation portal is available in Nynorsk (default) and English. This page
    explains where the portal text comes from, how the language versions are built and
    published, and how translations are kept up to date when the Nynorsk
    original changes.

## What is translated? {#kva-vert-omsett}

| Content | Translated? | Source |
|---|---|---|
| Headings, labels and explanations on the schema pages | Yes | The string catalog |
| Gen-doc pages (classes, slots, enums, types) | Yes, except LinkML terms | The string catalog via markers in the gen-doc templates |
| Nav menu, title, copyright, 404 page | Yes | The string catalog |
| Theme text (search, buttons) | Yes | Material, controlled by `theme.language` |
| Guide pages, front page, validation rules, domain descriptions | When a translated page exists | `x.<lang>.md` next to `x.md` |
| Model content (title/description from the schemas) | No | Shown in the original language |
| Version log (`CHANGELOG.md`) and validation messages | No | Generated by other tools |

LinkML terms that correspond to keys in the schema YAML (Slot, Enumeration, Mixin,
range, domain, Induced, property labels such as «Slot URI») stay unchanged in all
languages. Pages without a translation are shown in Nynorsk with the note
«Not yet translated», and the English schema pages have a note saying that
the model content is in Norwegian.

## Addresses {#adresser}

| Address | Content |
|---|---|
| `/nn/…`, `/en/…` | The portal pages per language, with a language selector at the top |
| `/<domene>/<modell>/<fil>` | Artifacts (`.ttl`, `.json`, `.yaml` …) on the same path as before, shared by all languages |
| Old page addresses without a language prefix | Redirect to `/nn/…` (with `#anchor`) |

The artifact addresses are unchanged because they are used by machines: catalog `.ttl` files are
harvested by Felles Begrepskatalog and Felles Datakatalog, and `heimeside` in
the model manifests is the information model identifier. The language selector keeps you on
the same page and the same `#anchor` when you switch language. Fixed heading anchors ensure that
the anchor is the same in all languages.

## Sources of text {#kjelder-for-tekst}

### The string catalog {#strengkatalogen}

`mkdocs/lib/i18n/strings.yaml` is the single source for all generated portal text:

```yaml
languages: [nn, en]
default_language: nn
language_names: {nn: Nynorsk, en: English}
strings:
  seksjon.kom_i_gang.valider_skjema:
    nn: Valider skjemaet mot {policy}-policy
    en: Validate the schema against the {policy} policy
```

- All languages are required for every key, and `{navn}` placeholders must be the same
  in all languages.
- Bash (`mkdocs/lib/sections/*.sh`, `publish.sh`): `i18n_load <lang>` once,
  then `$(t <nøkkel> navn=verdi)` (`mkdocs/lib/utils/i18n.sh`).
- Python (`mkdocs/lib/scripts/generate-*-md.py`): `load_catalog().t(nøkkel, lang, navn=verdi)`
  (`mkdocs/lib/scripts/i18n_strings.py`).
- Gen-doc templates (`src/assets/templates/docgen/*.jinja2`): markers
  `@@i18n:docgen.<nøkkel>@@`, which `publish.sh` replaces at the end. Translated
  headings have fixed anchors `{: #slug }` equal to the original slug.

`make i18n-check` validates the catalog and checks that all keys that are
used exist.

### Translated pages {#omsette-sider}

A translated page sits next to the original with the language code in the file name:
`mkdocs/docs/om.en.md`, `README.en.md`, `src/mcp-linkml-validator/policies/README.en.md`
and `src/linkml/<domene>/description.en.md`. Portal links in translated pages point
to the `/<lang>/` addresses.

`README.md` has tables that are generated automatically between
`<!-- BEGIN/END AUTO-GENERATED -->` markers. In `README.en.md` the markers are
left empty. At build time the tables are taken from `README.md` and the links in
them are rewritten to `/<lang>/`.

## Building {#bygging}

| Command | What happens |
|---|---|
| `make docs-publish` | Generates content for the default language in `mkdocs/docs/`, for every other language in `mkdocs/build/src-<lang>/`, build trees `mkdocs/build/<lang>/` + `mkdocs/build/rot/` (artifacts and redirects) and `mkdocs/build/mkdocs.<lang>.yml` |
| `make docs-build` | Builds all languages in parallel to `mkdocs/site/<lang>/` and puts `rot/` and the 404 page at the root. This is what is published to GitHub Pages |
| `make docs-serve [DOCS_LANG=en]` | Live preview of one language. Artifact links and the language selector do not work here |
| `make docs-serve-site` | Shows the fully built portal under the same base path as GitHub Pages, with all languages, artifacts and redirects |

## Translation and change detection {#omsetjing-og-endringsdeteksjon}

Each translation remembers a hash (sha256) of the Nynorsk original it was made
from:

- **Pages** have front matter that `publish.sh` removes before the content is used:

    ```yaml
    ---
    i18n:
      source: om.md
      source_hash: sha256:…
    ---
    ```

- **Catalog keys** have their hash in `mkdocs/lib/i18n/strings.lock.yaml`. The file
  is generated, so do not edit it by hand.

| Command | What happens |
|---|---|
| `make i18n-status [STRICT=1]` | Lists pages and keys that are missing a translation, are unstamped or are outdated because the original has changed. Gives warnings; `STRICT=1` fails on outdated/unstamped |
| `make i18n-stamp FILE=<x.en.md>` | Stamps a translated page after translation |
| `make i18n-stamp KEYS="k1 k2"` | Stamps catalog keys after the English value has been updated |
| `make i18n-stamp` | Stamps only keys that are missing a hash, e.g. new keys |

When you stamp a page under `mkdocs/docs/`, every heading in the translation gets a
fixed anchor (`{#slug}`) equal to the slug of the corresponding Nynorsk heading.
Stamping fails if the headings do not have the same number and levels as in
the original. Pages that are also shown on GitHub (`README.en.md`,
`policies/README.en.md`, `description.en.md`) do not get fixed anchors.

Workflow when the Nynorsk text has changed:

1. `make i18n-status` — see which translations are outdated.
2. Update `x.en.md` or the English value in `strings.yaml`.
3. `make i18n-stamp FILE=…` or `make i18n-stamp KEYS="…"`.
4. `make i18n-check`.

The translation is done by an LLM. The procedure is described in
[`.claude/rules/i18n-omsetjing.md`](https://github.com/AudunAutomat/linkml-datamodellering-no/blob/main/.claude/rules/i18n-omsetjing.md).

## New language {#nytt-sprak}

1. Add the language code to `languages` and a name to `language_names` in
   `strings.yaml`, and add a value for the language to all keys
   (`make i18n-check` fails until all are in place).
2. `make i18n-stamp DOCS_LANG=<lang>` to stamp the keys.
3. `make docs-publish && make docs-build` — the language automatically gets its own tree, its own
   config, its own search index and a place in the language selector.

Material must support the language code in `theme.language`.

## Known limitations {#kjende-avgrensingar}

- The table headers in the auto-generated README tables come from
  `generate-readme-tables.sh` and are in Nynorsk also on the English front page.
- The portal is built on Material for MkDocs, which receives critical maintenance until
  May 2027. The solution uses no plugin, only `theme.language` and
  `extra.alternate`, which are also supported in the successor Zensical.
