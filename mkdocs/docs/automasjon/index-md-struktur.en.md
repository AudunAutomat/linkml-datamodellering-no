# Structure of `index.md` per model {#struktur-for-indexmd-per-modell}

!!! note "Description"

    This page documents how the model documentation `index.md` file for each model is structured and generated by `mkdocs/publish.sh` (e.g. `mkdocs/docs/samt/samt-bu/index.md`, which is published as [SAMT - Kommunale integrasjonar/samt-bu](https://audunautomat.github.io/linkml-datamodellering-no/en/samt/samt-bu/) in the navigation menu on the left in this portal).

## Overview {#oversikt}

`index.md` works as the main page for each model in the documentation portal. The file is **generated automatically** by `mkdocs/publish.sh` (the function `process_schema()`) based on various sources:

- Generated artifacts from LinkML (gen-doc, PlantUML, validation results)
- Source files in `src/linkml/<domain>/<schema>/` (manifest, example, description.md, CHANGELOG.md)
- Dynamic parsing of metadata from the gen-doc output

The table below shows each section in `index.md`, what it contains, and where it comes from.

## Section order and sources {#seksjonsrekkjeflgje-og-kjelder}

| # | Section | Content | Source | Script/function |
|---|---|---|---|---|
| 1 | **Main heading** | `# <schema>` | Schema name from the directory name | `lib/sections/header.sh:generate_header()` |
| 2 | **Badge row** | Version, status, validation, license | Parsed from `generated/<domain>/<schema>/docs/index.md` (gen-doc) and `src/linkml/<domain>/<schema>/validation/<versjon>/<policy>.json` (validation result) | `lib/sections/badges.sh:generate_badges()` |
| 3 | **Official reference** (optional) | Info box with a link to an external specification (e.g. Digdir) | `build.yaml` (the `external_spec_url` field, optional) | `lib/sections/external_reference.sh:generate_external_reference()` |
| 4 | **About this model** (optional) | User-oriented introductory text | `src/linkml/<domain>/<schema>/description.md` (if it exists) | `lib/sections/description.sh:generate_description()` |
| 5 | **Getting started** | Quickstart guide with a validation command | `src/linkml/<domain>/quickstart.md` (optional, with `{{SCHEMA}}` and `{{SCHEMA_UNDERSCORE}}` substitution). Falls back to hard-coded logic if the file is missing. | `lib/sections/quickstart.sh:generate_quickstart()` |
| 6 | **Example data file** (optional) | YAML example (first 20 lines) + link to the full file | Extracted from `src/linkml/<domain>/<schema>/examples/<schema>-eksempel.yaml` | `lib/sections/example.sh:generate_example()` |
| 7 | **Model metadata** | Table with name, title, description, version, license, publisher, status, modification date, issue date — **verbatim values from the schema, not translated** | Extracted from `generated/<domain>/<schema>/docs/index.md` (gen-doc) — the `## Metadata` section | `lib/sections/metadata.sh:generate_metadata()` |
| 8 | **Publishing info** (optional) | Info box if the schema is published to Felles Begrepskatalog | Shown if `src/linkml/<domain>/<schema>/published-uris.lock` exists | `lib/sections/publishing_info.sh:generate_publishing_info()` |
| 9 | **Dependencies** | Hierarchical dependency tree (direct and transitive imports) | Generated from the `imports:` section of the schema → calls `mkdocs/lib/scripts/parse-dependency-tree.py` | `lib/sections/dependencies.sh:generate_dependencies()` |
| 10 | **ER diagram** | PlantUML SVG diagram (filtered version → local classes only) + link to the full version | Copied from `generated/<domain>/<schema>/diagrams/<schema>-filtered.svg` | `lib/sections/er_diagram.sh:generate_er_diagram()` |
| **11** | **Data model** | Link to the LinkML schema (source code) | `src/linkml/<domain>/<schema>/<schema>-schema.yaml` (relative link: `../../../src/linkml/<domain>/<schema>/<schema>-schema.yaml`) | `lib/sections/datamodell.sh:generate_datamodell()` |
| 12 | **Classes** | Class list per subset (Obligatorisk, Anbefalt, Valgfri, Andre) | Extracted from `generated/<domain>/<schema>/docs/index.md` (gen-doc) — the `## Classes` section and below | `lib/sections/classes.sh:generate_classes_section()` |
| 13 | **Slots** | Slot list (values, references, codes) | Part of the same extraction as Classes (gen-doc) | `lib/sections/classes.sh:generate_classes_section()` |
| 14 | **Enumerations** | Enumeration list | Part of the same extraction as Classes (gen-doc) | `lib/sections/classes.sh:generate_classes_section()` |
| 15 | **Types** | Type list (incl. imported types) with a "Defined in" column | Part of the same extraction as Classes (gen-doc) | `lib/sections/classes.sh:generate_classes_section()` |
| 16 | **Subsets** | Subset list | Part of the same extraction as Classes (gen-doc) | `lib/sections/classes.sh:generate_classes_section()` |
| **17** | **Generated artifacts** | Table with links to generated artifacts (**model manifest first**, then SHACL, JSON-LD, JSON Schema, OWL, RDF, Python, Protobuf, PlantUML etc.) | Generated dynamically from `mkdocs/docs/<domain>/<schema>/` and the `diagrams/` subdirectory. The model manifest is copied from `src/linkml/<domain>/<schema>/metadata/<schema>-manifest.yaml` | `lib/sections/artifacts.sh:generate_artifacts_table()` |
| 18 | **Validation results** | Validation status, error count, warning count + detailed list of errors/warnings | Generated by `mkdocs/lib/scripts/generate-validation-md.py` from `src/linkml/<domain>/<schema>/validation/<versjon>/<policy>.json` | `lib/sections/validation.sh:generate_validation_results()` → `generate-validation-md.py` |
| 19 | **Version log** | CHANGELOG content as plain Markdown | Copied from `src/linkml/<domain>/<schema>/CHANGELOG.md` — main heading removed, all others increased by one `#` | `lib/sections/changelog.sh:generate_changelog()` |
| 20 | **Contact** | Contact information (management responsibility, support) | Generated from `CODEOWNERS.md`. Matches the schema path against `path_patterns` per organization. | `lib/sections/contact.sh:generate_contact_info()` |

## Detailed source mapping {#detaljert-kjeldekartlegging}

### Badge row (section 2) {#badge-rad-seksjon-2}

Badges are generated from these sources:

| Badge | Parsed from | Lines in publish.sh |
|---|---|---|
| Version | `grep "^| Versjon" generated/<domain>/<schema>/docs/index.md` | 274 |
| Status | `grep "^| Status" generated/<domain>/<schema>/docs/index.md` | 275 |
| Validation | `src/linkml/<domain>/<schema>/validation/<versjon>/<policy>.json` (error_count) | 286-298 |
| License | `grep "^| Lisens" generated/<domain>/<schema>/docs/index.md` | 276 |

### Dependencies (section 9) {#avhengigheiter-seksjon-9}

The dependency tree is built in two steps:

1. **`build_dependency_graph()`** (publish.sh:173-215)
   - Finds the schema file: `src/linkml/<domain>/<schema>/<schema>-schema.yaml`
   - Extracts direct imports with `sed`/`grep` from the `imports:` section
   - Calls the Python script `mkdocs/lib/scripts/parse-dependency-tree.py` to build a hierarchical tree

2. **`parse-dependency-tree.py`**
   - Takes the schema name and direct imports as arguments
   - Builds a transitive dependency tree by following the import chain
   - Outputs an ASCII tree diagram (e.g. `linkml:types → common-ap-no → dcat-ap-no`)

### ER diagram (section 10) {#er-diagram-seksjon-10}

The PlantUML diagrams exist in two versions (see the CLAUDE.md section "PlantUML-diagram"):

- **Filtered version** (`<schema>-filtered.svg/puml`) — local classes only, prioritized in index.md
- **Full version** (`<schema>.svg/puml`) — all classes incl. imported ones, shown as the link "(full)"

Sources:

- Copied from `generated/<domain>/<schema>/diagrams/` to `mkdocs/docs/<domain>/<schema>/diagrams/`
- Generated by `make gen-plantuml` (source code: `Makefile:run_gen_plantuml`, `src/assets/scripts/makefile/filter_plantuml.py`)

### Data model (section 11) {#datamodell-seksjon-11}

**New section (2026-07-09):** Link to the LinkML schema as source code.

**Generation:** `lib/sections/datamodell.sh:generate_datamodell()`

**Output:**
```markdown
## Datamodell

Kjelde-datamodell i LinkML-format: [`<schema>-schema.yaml`](../../../src/linkml/<domain>/<schema>/<schema>-schema.yaml)
```

**Purpose:** Give direct access to the LinkML schema source code (YAML) from the model portal. This separates the LinkML schema from generated artifacts (which are in the "Generated artifacts" section).

**Source:** `src/linkml/<domain>/<schema>/<schema>-schema.yaml` (relative link from `mkdocs/docs/<domain>/<schema>/index.md`)

### Generated artifacts (section 17) {#generated-artifacts-seksjon-17}

**Updated (2026-07-09):** The model manifest was added as the first row of the table.

The artifact table now shows:

1. **Model manifest according to Modelldcat-ap-no** — `<schema>-manifest.yaml` (Informasjonsmodell instance, copied from `src/linkml/<domain>/<schema>/metadata/<schema>-manifest.yaml`)
2. SHACL Shapes — `<schema>-shapes.ttl`
3. JSON-LD Context — `<schema>-context.jsonld`
4. JSON Schema — `<schema>-schema.json`
5. ... (the rest of the artifacts)

**See:** [modellmanifest-generering.md](modellmanifest-generering.md) for complete documentation of manifest generation.

### Validation results (section 18) {#valideringsresultat-seksjon-18}

The validation results are generated by `mkdocs/lib/scripts/generate-validation-md.py`:

1. **Read the JSON file:**
   - `src/linkml/<domain>/<schema>/validation/<versjon>/<policy>.json`
   - Policy value taken from `build.yaml` (the `validation_policy` field, default: `bronze`)

2. **Find the latest version:**
   - `ls -v src/linkml/<domain>/<schema>/validation/` → grep version number (semver) → tail -n1

3. **Format the output:**
   - Status table (status, error count, warning count)
   - Numbered lists of errors and warnings (plain Markdown, not `<details>` blocks)
   - Each error/warning shows: rule name, affected element, error message

### Generated artifacts (section 16) {#generated-artifacts-seksjon-16}

The artifact table is built dynamically:

1. **Iterate through `ARTIFACT_ORDER`** (defined in publish.sh:~40):
   ```
   shacl_shapes.ttl context.jsonld schema.json schema.xsd openapi.yaml asyncapi.yaml ontology.ttl schema.ttl model.py schema.proto erdiagram.md
   ```

2. **Check whether the file exists** in `mkdocs/docs/<domain>/<schema>/`

3. **Add a row** with the artifact label (from `artifact_label()`) and a link

4. **PlantUML diagrams:**
   - Add a separate row with links to the filtered/full SVG and the PUML source code
   - Prioritize the filtered version (local classes only)

## Execution flow of `publish.sh` {#kyreflyt-for-publishsh}

`mkdocs/publish.sh` runs in four main steps (documented in CLAUDE.md):

1. **Step 1:** Clean previously generated domain directories from `mkdocs/docs/<domain>/`
2. **Step 2:** Generate content per domain and schema (in parallel) — runs `process_schema()` for each schema
3. **Step 2b/2c:** The same content for every other language, and build trees per language (see [Multilingual portal](fleirsprak.md))
4. **Step 3:** Generate `mkdocs/build/mkdocs.<lang>.yml` (dynamic nav menu from the `generated/` structure, labels from the string catalog)

`process_schema()` (step 2) generates `index.md` for one schema and runs in parallel for all schemas.

## Dependencies between generators {#avhengigheiter-mellom-generatorar}

Sequential dependency chain for building a complete `index.md`:

```
make gen-linkml (merge-imports)
  ↓
make gen-plantuml (diagram)
  ↓
make gen-doc (metadata, class lists)
  ↓
make mcp-linkml-valider-modell (validation results)
  ↓
mkdocs/publish.sh (build index.md)
  ↓
mkdocs serve (the portal is ready)
```

All of these run automatically via `make domain-<schema>` or `make domain` for all the domain models.

## Updating the content of `index.md` {#oppdatere-innhald-i-indexmd}

To change the content of a model's `index.md`:

| Desired change | Where to change it |
|---|---|
| Main title | Not editable — auto-generated from the schema name |
| Badge values | Change version/status/license in `src/linkml/<domain>/<schema>/<schema>-schema.yaml` (gen-doc parses this) |
| Official reference | Add `external_spec_url` to `src/linkml/<domain>/<schema>/build.yaml` |
| Introductory text | Create/edit `src/linkml/<domain>/<schema>/description.md` |
| Quickstart command | Edit `src/linkml/<domain>/quickstart.md` (or create the file if it is missing) |
| Example data file | Edit `src/linkml/<domain>/<schema>/examples/<schema>-eksempel.yaml` |
| Metadata table | Change metadata in `src/linkml/<domain>/<schema>/<schema>-schema.yaml` (gen-doc generates the table) |
| Dependencies | Change the `imports:` section of `<schema>-schema.yaml` |
| ER diagram | Change classes/slots in `<schema>-schema.yaml` and run `make gen-plantuml` |
| Class lists | Change classes/slots/enums in `<schema>-schema.yaml` and run `make gen-doc` |
| Validation results | Run `make mcp-linkml-valider-modell SCHEMA=...` → generates `validation/<versjon>/<policy>.json` |
| Version log | Edit `src/linkml/<domain>/<schema>/CHANGELOG.md` (follow the keep-a-changelog format) |
| Contact information | Change `annotations.utgiver` in `<schema>-schema.yaml` (silver annotation) |

**Important:** `index.md` must **never be edited manually** — all changes are overwritten the next time `make docs-publish` runs.

## Domain index (`index.md` per domain) {#domene-index-indexmd-per-domene}

Each domain (e.g. `mkdocs/docs/fint/index.md`, shown as "FINT - Fylkeskommunale integrasjonar" in the navigation menu) also has its own `index.md`, one level above the schema `index.md` files described above. This file is generated directly in `mkdocs/publish.sh` (the domain loop after the parallel job, not via `generate_schema_index()`), and contains:

1. **Main heading** — `# <domain_label>`, from `domain_label()` in `lib/utils/formatters.sh`
2. **Domain description** (optional) — the content of `src/linkml/<domain>/description.md`, rendered by `generate_domain_description()` in `lib/sections/domene_beskrivelse.sh`
3. **Model table** — one row per schema in the domain, with a link to the schema's `index.md` and a list of available artifacts (and publishing status, if the domain has published schemas)

`domene_beskrivelse.sh` lives in `lib/sections/` together with the schema-level sections, and is therefore sourced automatically by the same glob loop in `generate_index.sh` — but the function `generate_domain_description()` is called from the domain loop in `publish.sh`, not from `generate_schema_index()`.

**Updating the domain description:** edit `src/linkml/<domain>/description.md` (create the file if it is missing — the domain will then just show the title + table, as before).

## Source-of-truth hierarchy {#sannkjelde-hierarki}

```
src/linkml/<domain>/description.md                  ← SOURCE OF TRUTH for the domain description (optional)
src/linkml/<domain>/<schema>/<schema>-schema.yaml   ← SOURCE OF TRUTH for metadata, classes, slots
src/linkml/<domain>/<schema>/build.yaml             ← SOURCE OF TRUTH for generators + validation_policy
src/linkml/<domain>/<schema>/description.md         ← SOURCE OF TRUTH for the introductory text (optional)
src/linkml/<domain>/<schema>/examples/              ← SOURCE OF TRUTH for examples (optional)
src/linkml/<domain>/<schema>/CHANGELOG.md           ← SOURCE OF TRUTH for the version log
CODEOWNERS.md                                       ← SOURCE OF TRUTH for the publisher
  ↓
generated/<domain>/<schema>/                        ← Intermediate storage (gen-doc, PlantUML etc.)
  ↓
mkdocs/docs/<domain>/<schema>/index.md              ← OUTPUT (auto-generated, do not edit)
```

**Important:** The model metadata table (name, title, description, version, license, publisher, status, modification date, issue date) must show the values **verbatim as written in `<schema>-schema.yaml`** — not translated, even when the rest of the documentation page is in another language. The schema is the source of truth for all metadata values; editing or translating these values in the documentation would break the source-of-truth principle and create inconsistency between source code and published documentation.

## Related files {#relaterte-filer}

- **`mkdocs/publish.sh`** — main script (orchestration of steps 1-4)
- **`mkdocs/lib/copy_artifacts.sh`** — copies generated artifacts to `mkdocs/docs/`
- **`mkdocs/lib/generate_index.sh`** — orchestrates generation of `index.md` per schema
- **`mkdocs/lib/sections/*.sh`** — modules that each generate a section in the schema `index.md` (via `generate_index.sh`) or the domain `index.md` (`domene_beskrivelse.sh`, called directly from `publish.sh`)
- **`mkdocs/lib/utils/formatters.sh`** — helper functions for formatting (`artifact_label`, `domain_label`)
- **`mkdocs/lib/utils/metadata_parsers.sh`** — helper functions for parsing the manifest, version, validation
- **`mkdocs/lib/scripts/parse-dependency-tree.py`** — builds the dependency tree
- **`mkdocs/lib/scripts/generate-validation-md.py`** — formats validation results as Markdown
- **`src/assets/scripts/makefile/filter_plantuml.py`** — filters PlantUML diagrams to local classes only
- **`src/assets/templates/docgen/index.md.jinja2`** — Jinja2 template for gen-doc (generates `generated/<domain>/<schema>/docs/index.md`)
